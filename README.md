# mpi_wrap_gen

Create wrapper files for MPI profiler.

## Overview

`mpi_wrap_gen` reads a YAML configuration file, parses the official MPI standard PDF
(e.g. `mpi31-report.pdf`) to extract MPI function signatures from specified chapters,
and generates a C source file using configurable templates.

This tool replaces an earlier Perl-based workflow that relied on a plain-text
conversion of the MPI standard.

## Features

- Reads configuration from a YAML file (PDF path, output path, chapter list, templates)
- Extracts MPI function signatures directly from the MPI standard PDF
- Identifies chapter boundaries via PDF outline (bookmark) tree
- Parses function names and parameter lists from the configured chapters
- Generates C source files using Python-style format string templates

## Requirements

- Rust 2021 edition (1.70+)

## Building

```bash
cargo build --release
```

## Usage

```bash
mpi_wrap_gen [OPTIONS] <CONFIG_FILE>
```

### Options

| Option                | Description                                       |
|-----------------------|---------------------------------------------------|
| `-v`, `--verbose`     | Enable verbose output (default: false)            |
| `-D`, `--dry-run`     | Run in verbose mode without generating output     |
| `-u`, `--underscores` | Number of underscores preceding each Fortran call |
| `--no-prettify`       | Disable prettifying the generated output code     |
| `-h`, `--help`        | Print help                                        |
| `-V`, `--version`     | Print version                                     |

### Arguments

| Argument      | Description                         |
|---------------|-------------------------------------|
| `CONFIG_FILE` | Path to the YAML configuration file |

### Example

```bash
mpi_wrap_gen config.yml
mpi_wrap_gen --verbose config.yml
mpi_wrap_gen --dry-run config.yml
mpi_wrap_gen --no-prettify -u 2 config.yml
```

## Configuration File

The configuration file is a YAML document with the following fields:

```yaml
mpi_pdf: "mpi31-report.pdf"      # Path to the MPI standard PDF
output_file: "mpi_wrapper.c"     # Path for the generated C output file
chapters:                        # List of chapter numbers to process
  - 3
  - 5
excludes:
  - "Init"
  - "Finalize"
templates:
  header: |
    /* Generated by mpi_wrap_gen */
  ch_init: "/* List of MPI calls for chapter  %(chapter_number)d %(chapter_title)s*/\n"
  ch_body: "  /*  MPI_%(mpi_call_name)s */\n"
  bar_init: "/* List of barrier calls for chapter  %(chapter_number)d %(chapter_title)s*/\n"
  bar_body: "  /*  MPI_%(mpi_call_name)s */\n"
  footer: "/* end of file */\n"
```

### Template Placeholders

Templates use Python-style format strings (`%(name)type`):

| Placeholder             | Type    | Description                                  |
|-------------------------|---------|----------------------------------------------|
| `%(chapter_number)d`    | integer | Chapter number                               |
| `%(chapter_title)s`     | string  | Chapter title from the PDF outline           |
| `%(mpi_call_name)s`     | string  | MPI function name without the `MPI_` prefix  |
| `%(mpi_call_name_lc)s`  | string  | `%(mpi_call_name)s` converted to lower case  |
| `%(mpi_call_name_id)s`  | string  | `%(mpi_call_name_lc)s` with an `_id,` suffix |
| `%(mpi_call_params)s`   | string  | Language dependent parameter list without () |
| `%(mpi_call)s`          | string  | `%(mpi_call_name)s` with parameter list      |
| `%(u)s`                 | string  | "_".repeat(underscores)                      |

The `header` template is emitted once at the start of the output. For each chapter
with MPI calls, `ch_init` is emitted once (using the first call found), followed by
`ch_body` once per MPI call. The `footer` template is emitted once at the end.

`excludes` is optional. Entries are matched case-insensitively, accept either bare
MPI names (`init`) or `MPI_`-prefixed names (`MPI_Init`), and also suppress matching
`*_barrier` entries in the collective barrier section.

If any of the processed chapters has a title containing the word "collective"
(case-insensitive), a barrier section is appended before the footer. `bar_init` is
emitted once for that section (using the first barrier call found), followed by
`bar_body` once per barrier call. In the barrier templates, `%(mpi_call_name)s`
contains the MPI function name with the `_barrier` suffix already appended
(e.g. `Bcast_barrier`).

## Project Structure

```text
src/
├── main.rs          # Entry point: parses args, reads config, orchestrates generation
├── cmdline.rs       # CLI argument parsing (clap)
├── config.rs        # YAML config deserialization
├── chapters.rs      # PDF outline traversal, chapter-to-page mapping
├── mpi_calls.rs     # MPI function signature extraction and parameter parsing
├── listings.rs      # Orchestrates per-chapter extraction and output assembly
└── template.rs      # Python-style template substitution (dynfmt2)
test_data/
├── mpi_call_xmp.pdf # Sample PDF for MPI call extraction tests
└── test_outline.pdf # Sample PDF for chapter outline tests
```
